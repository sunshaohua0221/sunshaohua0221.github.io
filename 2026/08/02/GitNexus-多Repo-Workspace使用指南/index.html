GitNexus 多 Repo Workspace 使用指南

最近在一个由「多个 repo 组成一条业务线」的工作区里做开发，让 AI 工具帮忙读代码、分析影响面时，最大的两个痛点逐渐凸显：

  1. 搜索不够精准：AI 工具默认的 grep/glob 搜索方式在搜代码时容易遗漏，尤其是做影响面分析时，常常漏掉跨 repo 的调用关系。
  2. 费 token：动不动就把整仓代码塞给模型，token 消耗飞快。

GitNexus 正好补上这块短板。它是一套零服务端（Zero-Server）的代码智能引擎，完全跑在本地/浏览器侧：丢进一个 git 仓库（GitHub / GitLab / Azure / Local）或 ZIP 包，就能得到一张可交互的知识图谱，并内置 Graph RAG Agent。它会把整个代码库索引成知识图谱——每一个依赖、调用链、聚类和执行流——再通过智能 MCP 工具暴露出来，让 AI Agent 不再「搜不到代码」。

选用 GitNexus 的两大收益：节约 token；提升 AI 搜索代码的精准度，尤其是影响面分析这类容易遗漏的场景。

本文以 /Users/dev/multi-repo-workspace 这类多 repo 工作区为例（下文统一用「用户中心业务线」做演示），记录如何在一条业务线中完整接入 GitNexus，覆盖安装、索引、Git 排除、group 设置、MCP/Web 使用到日常维护的全流程。

8.2 中文需求要先改写成英文 query

GitNexus 的本地 embedding、代码标识符、process summary 对英文技术词更友好。不要直接把中文需求丢给 GitNexus。示例对照：

中文意图 推荐 query
用户修改昵称时如何校验唯一性 update nickname validate uniqueness duplicate check
创建订单后如何扣减库存 create order deduct inventory stock decrement
用户上传头像后如何生成缩略图 upload avatar generate thumbnail resize image
用户评论被删除后如何清理缓存 delete comment clear cache invalidate
消息推送失败时如何重试 message push fail retry queue backoff

8.3 什么时候用 native search

优先 native search 的场景：

  • 已知精确文件名或路径。
  • proto / schema / config 精确字段查询。
  • 只需要同目录 / 同 package 的局部代码风格。
  • GitNexus query 没有返回候选或返回明显噪声。

8.4 什么时候用 GitNexus

优先 GitNexus 的场景：

  • 跨 repo 业务线搜索。
  • 查找相似流程、复用组件、调用链。
  • 需要 context 看 callers / callees。
  • 需要 impact 看影响面。
  • 设计阶段、任务执行前 reuse scan、设计评审、代码评审。

9. Embeddings 建议

本机支持 local embeddings，但不建议对所有 repo 立即全量开启。推荐只对核心 repo 开启 embeddings 做语义查询增强：

适合开启 embeddings 的 repo：

Repo 原因
user-api-server 用户主流程、资料、权限、profile 读写
user-worker 异步任务、消息消费主流程
user-common 共享工具、基础组件
user-admin 后台管理、配置
user-gateway 外部 API / gateway 入口

不建议全量开启的原因：

  • 索引耗时明显增加。
  • 宽泛 group query 的噪声不一定靠 embeddings 解决。
  • 精确 symbol / API / proto / schema 场景更适合 graph / FTS / native search。

12. 常见问题

Q1：每个 repo 都要执行 gitnexus setup 吗？
不需要。gitnexus setup 是本机 / 编辑器级别的一次性配置，会自动检测并连接支持的编辑器 / Agent 工具。每个 repo 需要的是 gitnexus analyze。如果某个工具需要手动配置，通用 server 命令是 gitnexus mcp。

Q2：为什么看不到 .gitnexus/ 被提交？
因为 .gitnexus/ 是本地索引目录，已加入 .git/info/exclude，可以不提交。

Q3：为什么有些 repo 的 AGENTS.md 仍显示 modified？
因为如果 AGENTS.md 已经被 git 跟踪，.git/info/exclude 不会隐藏它的变化。可选择保留本地修改不提交，或谨慎使用：

Q4：GitNexus Web 代码面板显示「内存中没有代码内容」怎么办？
先确认后端 API 是否能读文件。如果 API 正常，通常是 Web UI 前端状态问题。可尝试：

  • 刷新页面。
  • 点击其他文件后再点回来。
  • 避免点击目录节点后马上查看代码面板。

本机已 patch /api/file，目录请求现在返回 400 Path is a directory，不再返回 500。

13. 最佳实践总结

  1. 每个 repo 做 analyze，gitnexus setup 只做一次；手动接入 MCP 时使用通用命令 gitnexus mcp。
  2. 多 repo 业务线用 knowledge_domain 作为 GitNexus group 名。
  3. repo 加 group 后记得 gitnexus group sync。
  4. GitNexus 用于候选发现、调用图、影响面分析。
  5. 任何结论必须回到源码 file:line 验证。
  6. 中文需求先改写成英文领域词和可能的代码词。
  7. 先 group 粗搜，再 subgroup / repo 精搜。
  8. Embeddings 优先给核心 repo，不建议一开始全量开启。
